Methodology

This report was generated using Claude Code (Claude Opus 4.6) with full transparency. Here is exactly how:

1. Data Collection

gh pr list --repo h2oai/h2ogpte --state merged \
  --search "merged:>=2026-01-10" --limit 500 \
  --json number,title,body,author,mergedAt,url

gh pr list --repo h2oai/h2ogpte --state open \
  --limit 200 \
  --json number,title,body,author,url

This returned 391 merged + 97 open = 488 total PRs from 20 unique contributors.

2. Classification Prompt

Each PR title and body snippet was classified by Claude with this criteria:

Include: Security fixes, CVE remediation, access control/RBAC, API rate limiting, scalability/performance, MCP server, collection migration, telemetry/observability, infrastructure (autoscaling, IAM, Helm), UI/UX enterprise quality (error handling, settings, progress), client SDK, model management, data pipelines, connectors, i18n.

Exclude: Version bumps, CI/CD fixes (unless security), backport PRs (duplicate the original), internal dev tooling (CLAUDE.md, worktree skills, Makefile configs), test-only fixes, minor cosmetic tweaks, narrow internal bug fixes, bot/automation PRs, h2ogpt_internal updates, code refactoring with no user-visible impact.

3. Human Review

The classification (what to include/exclude) was done entirely by Claude based on the criteria above. Human review was limited to:

  • Mapping GitHub usernames to display names (e.g., pseudotensor → Jon)
  • Adding PRs that were missed because they were authored under the app/claude bot account (e.g., PgBouncer #8899, MCP server #8902)

No PRs were manually added or removed based on subjective judgment — the include/exclude decision was fully automated.

4. Result

141 of 488 PRs (29%) were classified as enterprise-relevant. The remaining 347 were version bumps, backports, CI fixes, internal tooling, and narrow bug fixes.
